# 15_COLOR_SYSTEM

**Project:** ShrotiHost  
**Document Version:** 1.0  
**Status:** Draft

---

# Purpose

This document defines the official color system for the ShrotiHost design language.

Every interface, illustration, component, chart, animation, and future application must use this color system to maintain a consistent visual identity.

---

# Design Philosophy

Colors should communicate:

- Trust
- Performance
- Innovation
- Reliability
- Simplicity

Avoid excessive saturation or distracting color combinations.

---

# Theme Support

The platform must support:

- Light Theme
- Dark Theme

Both themes should feel equally premium and accessible.

---

# Brand Color Categories

## Primary Brand Color

Used for:

- Primary buttons
- Links
- Highlights
- Interactive elements

---

## Secondary Brand Color

Used for:

- Supporting accents
- Illustrations
- Gradients
- Decorative elements

---

## Neutral Colors

Used for:

- Backgrounds
- Cards
- Borders
- Text
- Layout surfaces

---

# Semantic Colors

## Success

Used for:

- Successful actions
- Completed tasks
- Positive system messages

---

## Warning

Used for:

- Caution
- Recommendations
- Important notices

---

## Error

Used for:

- Validation
- Failures
- Critical issues

---

## Information

Used for:

- Tips
- Documentation
- Neutral notifications

---

# Surface Hierarchy

Define multiple surface levels:

- Page Background
- Section Background
- Cards
- Floating Panels
- Dialogs
- Dropdowns

Each level should provide sufficient visual separation.

---

# Text Colors

Use dedicated colors for:

- Primary Text
- Secondary Text
- Muted Text
- Disabled Text
- Inverse Text

Maintain accessibility contrast at all times.

---

# Border Colors

Border colors should remain subtle.

Avoid high-contrast borders unless required for accessibility.

---

# Interactive States

Every interactive element should define colors for:

- Default
- Hover
- Active
- Focus
- Disabled

---

# Gradients

Gradients should be used sparingly.

Approved locations:

- Hero section
- Feature highlights
- Premium call-to-action sections

Avoid gradient-heavy layouts.

---

# Glass Surfaces

Glassmorphism should be reserved for:

- Floating navigation
- Dialogs
- AI Assistant
- Premium cards

Ensure readability over blurred backgrounds.

---

# Charts & Data Visualization

Use a consistent palette for:

- Revenue
- Performance
- Visitors
- Uptime
- Alerts

Charts should remain readable in both themes.

---

# Accessibility

Minimum requirements:

- WCAG AA contrast
- Visible focus indicators
- Readable text on every surface

Accessibility takes priority over aesthetics.

---

# Future Theming

The system should support future additions such as:

- Seasonal themes
- Event themes
- Customer dashboard themes

without changing component structure.

---

# Acceptance Checklist

Every new color must:

- Have a defined purpose.
- Meet accessibility standards.
- Be reusable.
- Work in both themes.
- Align with the ShrotiHost brand.
