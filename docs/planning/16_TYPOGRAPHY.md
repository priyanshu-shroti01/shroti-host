# 16_TYPOGRAPHY

**Project:** ShrotiHost
**Document Version:** 1.0
**Status:** Draft

---

# Purpose

This document defines the official typography system for ShrotiHost. Consistent typography improves readability, reinforces the brand, and creates a unified user experience across the website and future products.

---

# Typography Principles

- Readability first
- Consistency across all pages
- Clear visual hierarchy
- Responsive scaling
- Accessibility by default

Typography should communicate professionalism and simplicity.

---

# Font Strategy

## Primary Typeface

Use a modern sans-serif font for all user interfaces.

Requirements:

- Excellent readability
- Multiple font weights
- Good multilingual support
- Optimized for web performance

---

## Secondary Typeface

Optional display font for hero sections or marketing campaigns.

Use sparingly.

---

# Font Weights

Recommended hierarchy:

- Light
- Regular
- Medium
- Semi Bold
- Bold

Avoid excessive weight variations.

---

# Typography Scale

Use a consistent scale:

- Display
- H1
- H2
- H3
- H4
- H5
- H6
- Body Large
- Body
- Small
- Caption

Maintain proportional sizing across all breakpoints.

---

# Line Height

Guidelines:

- Headings: Compact
- Body Text: Comfortable
- Long-form Content: Generous spacing

Avoid cramped text.

---

# Letter Spacing

Use tighter spacing for large headings.

Use normal spacing for body text.

Do not apply excessive tracking.

---

# Paragraph Spacing

Separate ideas with consistent spacing.

Prefer whitespace over divider lines.

---

# Text Alignment

Default:

- Left aligned

Center alignment should only be used in:

- Hero sections
- Marketing banners
- Empty states

Avoid justified text.

---

# Links

Links should be:

- Clearly distinguishable
- Accessible
- Consistent across themes

Hover and focus states must be visible.

---

# Responsive Typography

Scale typography gracefully across:

- Mobile
- Tablet
- Laptop
- Desktop
- Large displays

Never rely on fixed pixel values alone.

---

# Accessibility

Typography must:

- Meet WCAG readability standards
- Support zoom without breaking layouts
- Maintain sufficient contrast
- Avoid excessively small text

---

# Code Blocks

Developer documentation should use a dedicated monospace font.

Code examples should include:

- Proper spacing
- Syntax highlighting
- Copy button (future)

---

# Content Guidelines

Keep paragraphs short.

Use descriptive headings.

Prefer bullet lists where appropriate.

Avoid large walls of text.

---

# Acceptance Checklist

Every page should:

- Follow the typography scale
- Maintain hierarchy
- Be readable on all devices
- Match brand guidelines

---

# Future Considerations

Typography should remain flexible enough to support:

- Documentation portal
- Customer dashboard
- AI assistant
- Mobile application
- Future internationalization
